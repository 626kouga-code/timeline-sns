# 非機能要件

[目次に戻る](README.md)

| 区分 | 要件 |
| --- | --- |
| セキュリティ | 通信はすべて HTTPS。パスワードは BCrypt でハッシュ化して保存する |
| セキュリティ | アクセストークン（JWT、有効期限 15 分）はフロントのメモリにだけ保持する。リフレッシュトークン（14 日）は HttpOnly・Secure・SameSite=Strict の Cookie で扱い、使うたびに新しいものに入れ替える。DB にはハッシュ値だけを保存する |
| セキュリティ | フロントと API を同じドメインで公開し（`/api/*` を API へ振り分け）、Cookie がクロスサイトにならないようにする |
| セキュリティ | 更新・削除の権限（本人のみ、管理者のみ）はサーバー側で必ず確認する |
| セキュリティ | XSS 対策として、投稿本文は React の標準エスケープで表示し、HTML としては描画しない |
| セキュリティ | レート制限：ログイン試行は 1 IP あたり 10 回/10 分、投稿は 1 ユーザーあたり 30 件/時、登録は 1 IP あたり 5 件/時 |
| 画像 | アップロードは Spring Boot を経由する。ファイルの中身から形式を判定し、Exif を除去して、サムネイル（長辺 640px）と表示用（長辺 2048px）を生成してから S3 に保存する |
| 性能 | タイムラインの初回表示は 2 秒以内（100 ユーザー同時接続時）。一覧取得はカーソル方式のページング（20 件単位） |
| 対応環境 | PC・スマートフォンの最新ブラウザ（Chrome / Safari / Edge / Firefox）。レスポンシブ対応 |
| 可用性 | 目標稼働率 99%（個人運用のため、計画メンテナンスによる停止は許容する） |
| 法務 | 利用規約・プライバシーポリシーを公開前に用意する。退会時にユーザーデータを削除する |
